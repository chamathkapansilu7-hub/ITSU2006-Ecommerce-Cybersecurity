# Change and Configuration Management Plan

## 1. Purpose

This document defines the proposed change and configuration management procedures for the ITSU2006 E-Commerce Cybersecurity Risk Assessment and Mitigation Strategy Implementation project.

## 2. Change Management Objectives

The change management process aims to prevent uncontrolled modifications to the project scope, schedule, resources, deliverables and cybersecurity risk mitigation strategy.

## 3. Change Request Process

1. **Change Identification:** A team member identifies a proposed change and records it in the change request log.
2. **Change Submission:** The requester documents the reason, requested modification, expected benefits and urgency.
3. **Impact Assessment:** The project team assesses the effect on project scope, schedule, costs, resources, quality and risks.
4. **Review and Approval:** The designated project authority reviews the request and approves, rejects or defers it.
5. **Implementation Planning:** Approved changes are assigned an owner and implementation date.
6. **Configuration Update:** Relevant project documents, Jira tasks, schedules and GitHub files are updated.
7. **Verification and Closure:** Changes are reviewed against acceptance criteria and formally closed.

## 4. Change Control Responsibilities

| Role | Responsibility |
|---|---|
| Project Leader | Coordinates change requests and maintains the change log |
| Risk Assessment Lead | Evaluates cybersecurity risk implications |
| Planning Coordinator | Evaluates schedule and resource impacts |
| Documentation and Quality Coordinator | Reviews documentation consistency and change verification |
| Academic Supervisor | Reviews major changes when academic approval is required |

## 5. Configuration Management

GitHub serves as the proposed central repository for version-controlled project documentation. The `main` branch represents the approved project documentation baseline. Changes should use meaningful commit messages, and substantial updates should be reviewed through pull requests.

Jira is used to manage tasks, responsibilities, schedules and project status.

## 7. Issue Escalation

Issues affecting critical deliverables, deadlines or cybersecurity risk assumptions should be reported to the project leader. Issues that cannot be resolved within the team's agreed response period should be escalated to the designated academic supervisor when appropriate.

## 8. Review and Audit

The team should review change requests and document versions during planned project coordination meetings. Approved changes must maintain traceability between Jira work items, GitHub revisions and the final report.

## 9. Academic Simulation Disclaimer

This is a proposed governance framework for academic project management. It does not claim that the illustrative changes have occurred or been approved.
